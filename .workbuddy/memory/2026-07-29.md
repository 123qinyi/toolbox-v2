## 首次 push 及问题修复
- commit `9b38583`（lucide-react 降级）已成功 push 到 GitHub main
- **根因定位**：PortableGit 系统级 gitconfig 配了 GCM（Git Credential Manager），GCM 凭据缓存在 Windows 凭据管理器（机器绑定），迁移后丢失。GCM 又覆盖了 `credential.helper store`，导致 git 认证链断裂 → 401
- **彻底修复**：用空字符串 `git config --global credential.helper ""` 清除系统级继承的 GCM，再 `--add credential.helper store` 设为唯一 helper。push URL 恢复干净地址（去掉内嵌 PAT），`git push origin main` 正常工作
- sync.sh 已更新：setup 模式改用 credential.helper store 方案，不再内嵌 PAT 到 URL

## sync.sh 同步逻辑修复
- **发现问题**：sync 模式只做"本地 → repo"备份，不做"repo → 本地"恢复。多设备切换时，设备 B 的旧身份文件会覆盖设备 A 推送的新版本
- **修复方案**：sync 模式改为"备份本地 → 提交 → git pull → 恢复到本地 → 推送"四步流程
  - 先备份本地到 repo 并提交（保存本机状态）
  - git pull 合并远程变更（如两台设备改了同一文件，git 报冲突让用户手动解决）
  - 恢复 repo 文件到 ~/.workbuddy/ 和工作区日志目录（获取其他设备最新版本）
  - 推送合并后的结果
- 日常切换简化为统一一条命令：`bash .workbuddy/memory/sync.sh`（离开和到达都跑这个）
